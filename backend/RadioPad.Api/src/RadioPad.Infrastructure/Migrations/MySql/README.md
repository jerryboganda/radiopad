# MySQL / MariaDB migrations (generated)

This folder holds the EF Core migrations for `MySqlRadioPadDbContext` (RADIOPAD_DB_PROVIDER=mysql|mariadb).
It is **generated by the `mysql-migrations` workflow, never hand-written**.

Why a separate set: the SQLite migrations next to this folder hard-code `TEXT`/`INTEGER` columns (Guid keys as
TEXT cannot be indexed on MySQL). EF loads only migrations tagged `[DbContext(typeof(MySqlRadioPadDbContext))]`
for that context, so the two histories never mix.

Until the first migration exists, a MySQL deployment refuses to start with
"MySQL migrations have not been generated yet" (see `Program.cs`).

Every later schema change needs **two** migrations: one for the SQLite/Postgres history
(`--context RadioPadDbContext`) and one here (`--context MySqlRadioPadDbContext`).

Generate (CI, needs dotnet-ef 8.0.x; no database connection required). The `mysql-migrations` workflow runs exactly
this with `ASPNETCORE_ENVIRONMENT=Testing` (the host builds without touching Hangfire, secrets or a database;
`Development` also works but starts more of the host):

    ASPNETCORE_ENVIRONMENT=Testing RADIOPAD_DB_PROVIDER=mysql \
    ConnectionStrings__RadioPad="Server=localhost;Database=radiopad;User=u;Password=p;SslMode=None" \
    dotnet ef migrations add <Name> \
      --context MySqlRadioPadDbContext \
      --project backend/RadioPad.Api/src/RadioPad.Infrastructure \
      --startup-project backend/RadioPad.Api/src/RadioPad.Api \
      --output-dir Migrations/MySql
